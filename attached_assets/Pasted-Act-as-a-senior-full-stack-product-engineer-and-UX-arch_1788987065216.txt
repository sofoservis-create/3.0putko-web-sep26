Act as a senior full-stack product engineer and UX architect with extensive experience building accommodation marketplaces such as Airbnb, Booking.com, Vrbo, and modern short-term rental SaaS products.

I want you to perform a complete audit and redesign proposal for the **Host Profile, Host Dashboard, and Host Onboarding experience** of our accommodation platform.

## IMPORTANT EXISTING SYSTEM CONSTRAINT

We **already have the accommodation creation / adding accommodation logic implemented**.

Do NOT assume this needs to be rebuilt from scratch.

Do NOT replace the current accommodation creation architecture unless you identify a concrete technical or UX reason why part of it must change.

Your job is primarily to audit:

* how users enter the existing accommodation creation flow,
* what happens before it,
* what happens after it,
* how the Host Dashboard connects to it,
* how existing drafts are surfaced,
* how hosts return to incomplete properties,
* how newly created properties appear inside the Host area,
* how the first-property experience differs from adding a second or tenth property,
* how the current accommodation creation flow can be integrated more seamlessly into the overall Host experience.

You should inspect the existing accommodation creation implementation first and treat it as the **current source of truth**.

Where possible:

**reuse existing logic, routes, backend functionality, validation, database structure, and components.**

Improve or restructure only the UX shell, navigation, entry points, sequencing, or individual steps where there is a clear benefit.

Do not create a parallel duplicate accommodation creation system.

# PRODUCT CONTEXT

The platform is focused primarily on **short-term accommodation rentals in Slovakia**, with expansion to nearby European markets later.

Our core principles are:

* Mobile-first UX
* Extremely simple host onboarding
* Minimal cognitive load
* Clean, premium visual design
* No unnecessary screens or navigation
* Clear progress indicators
* Strong guidance for inexperienced hosts
* Stripe-based online payments
* Hosts should always know what they need to do next
* The platform should feel closer to Airbnb in UX quality, but should not blindly copy Airbnb
* Adapt the flow to Slovak hosts, apartments, cottages, pensions, glamping properties, guest houses, and professional operators

Use **Airbnb Host UX as a product benchmark**, particularly for information hierarchy and usability, but design around our existing product architecture.

# UX PRINCIPLES

Apply these principles throughout the audit.

## 1. Progressive disclosure

Do not expose advanced settings before they are relevant.

## 2. Strong empty states

Never show:

"No properties."

Show something actionable:

"You haven't added an accommodation yet."

[Add your first accommodation]

## 3. One primary action per screen

Avoid competing CTAs.

## 4. Action-first Host Dashboard

Show problems, tasks, and upcoming operations before vanity metrics.

## 5. Preserve working logic

Do not rebuild functioning backend systems for cosmetic reasons.

## 6. Guided editing

Use progressive forms, cards, context, and status indicators instead of huge settings pages.

## 7. Autosave

Where supported by the current architecture, changes should save automatically.

## 8. Preview

Hosts should frequently have access to:

**Preview as guest**

## 9. Consistency

Adding the first property and adding the tenth property should use the same underlying accommodation system.

Only the surrounding guidance should change.
